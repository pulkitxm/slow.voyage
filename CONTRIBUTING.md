# Contributing to slow.voyage

Thank you for helping improve slow.voyage. Bug reports, driving and visual
feedback, performance reports, tests, and code are welcome.

## Before You Start

- Search existing issues and pull requests before opening a duplicate.
- For a substantial feature, a new vehicle or landscape, or a change to the
  driving model, open an issue first so the approach can be discussed.
- Keep changes focused. Separate unrelated fixes into separate pull requests.
- Never include credentials, `.env` files, browser captures from `.review/`, or
  generated build output from `dist/`.

## Development Setup

slow.voyage requires Bun 1.4.2 or newer and Git. The browser suites also need a
Chrome or Chromium install.

```sh
git clone https://github.com/pulkitxm/slow.voyage.git
cd slow.voyage
bun install
bun run dev
```

The development server runs on <http://localhost:3002>. `bun install` also
installs the Lefthook pre-commit hook.

## Required Checks

Every commit runs `bun run validate` through the pre-commit hook: Biome
formatting and linting, strict YAML 1.2 validation, route generation, application
and worker type checks, and the game tests. Do not bypass the hook.

Before opening a pull request, also run:

```sh
bun install --frozen-lockfile
bun run build
bun run test:offline
bun run test:browser
```

Use `bun run format` to apply formatting.

## Code Guidelines

- Do not add code comments. Use names and structure to carry the meaning.
- Keep the game fully playable offline. Do not add runtime requests to outside
  services or assets loaded from a CDN.
- Models and textures are generated by the scripts in `tools/assets/`. Change the
  generator and regenerate rather than editing a binary asset by hand, and do not
  add third-party models, scans, photographs, or sounds. See
  [docs/assets.md](docs/assets.md).
- Keep rendering and input responsive on low-end and touch devices. Measure frame
  time and input response for changes to the world, dynamics, or cameras.
- Every action must stay reachable from the keyboard, and touch and controller
  input must keep working.
- Update `README.md` and the in-game help when controls or user-facing behavior
  change.

For visual changes, capture before and after with `bun run review:capture
<label>` and compare the frames in `.review/<label>/index.html`.

## Pull Requests

A pull request description is one line that states what changed and why. Keep
the diff focused and add tests for changed behavior. After verification is
complete, post one short evidence comment that shows the end result through a
screenshot or recording when the change has something to see.

Maintainers may request changes before merge. By contributing, you agree that
your contribution is licensed under the repository's [MIT License](LICENSE).

## Reporting Security Issues

Do not publish exploitable security issues in a public issue. Follow
[SECURITY.md](SECURITY.md) and use GitHub's private vulnerability reporting form
instead.

## Releases

A push to `main` builds the site with Bun and deploys it to <https://slow.voyage>
through the `Pages` workflow. There are no versioned releases.
